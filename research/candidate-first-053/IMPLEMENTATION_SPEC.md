# 053 implementation and fixed preparation details

This supplement resolves deterministic implementation details without changing the independently accepted design, scorer, sources or gates. No actual-bank control/K4 scores existed when it was written.

## Files and commands

- `reference.py`: independent Python normalization, twelve tableau formulas, language model training/scoring and conditional permutations.
- `prepare_source_plan.py`: raw-source inventory; original plan retained.
- `prepare_data.py windows`: score-blind passage selection and exact cross-role overlap checks.
- `prepare_data.py controls`: literal144 control specifications/ciphertexts, without scoring.
- `prepare_data.py train`: fixed training counts/log tables and calibration-only ceiling.
- `native053.c`, `native.py`: independent C implementation and explicit binary build receipt. Build with `python -c 'import native; native.build_native()'`; compiler flags disallow fast-math and floating-point contraction.
- `python -m unittest -v test_reference test_native test_runner`: synthetic-only arithmetic, probability, native equivalence, stage and audit-binding tests. The synthetic benchmark report is regenerated by tests and is evidence, not an experimental input.
- `python run_experiment.py freeze`: requires a passed independent implementation certificate binding every required input hash. Does not score controls or target.
- `python run_experiment.py controls`: requires unchanged freeze; runs all144 targets and15,696 full-bank conditional nulls. Existing result files are never silently overwritten.
- `python run_experiment.py target --ciphertext '<canonical97letters>'`: additionally requires passed empirical gate and hash-bound independent pretarget audit. Operationally requires separate parent authorization; implementation/audit certificates alone are not target authorization.

## Exact deterministic preparation

Source document IDs are the collection-relative filenames in CONTROL_SOURCE_PLAN.json. Newly authored documents use `novel/K001` through `novel/K012`; their original files and authoring log are retained. Three author topic labels omit an optional leading article (`a`/`an`); matching ignores just that leading article, without modifying source prose or raw files.

The window RNG label is `window-grid|<role>|<document_id>` under the protocol's SHA256-derived RNG. Every source has one shuffled grid and one persistent cursor. Selection order is:

1. Calibration sources in sorted document-ID order, up to64 windows per Gutenberg document and4 per inaugural document.
2.48 ordinary published-source windows by repeated round-robin over sorted document IDs: first36 are positives and the last12 are true-plaintext-absent controls.
3.12 word-token stress sources, again round-robin, continuing those SAME grids/cursors and additionally enforcing whole ASCII-letter-run boundaries.
4.24 difficult-style sources by sorted-document round-robin.
5. One window from each sorted novel document.

All accepted windows are globally distinct97-letter strings. Every one of its50 contiguous48-letter substrings is checked against every full normalized document in another role, including full unused training tails and all novel documents. Only a first detected overlap is needed to reject a window; its evidence is logged. Same-role sources are document-disjoint from other roles; within-document selected offsets stay on the single512-spaced grid. The resulting436 windows comprise340 calibration,48 ordinary prose,12 stress,24 difficult-style and12 novel.165 proposals failed only the stress whole-token-boundary requirement; no cross-role48 overlap or duplicate97 rejection occurred. No window was selected by language/cryptographic scores.

Uniform-key RNG labels: `uniform-key|0` through `uniform-key|23`. Letter-permutation labels: `letter-permutation|<paired positive control ID>`. Word-token labels: `word-token-permutation|<STRESS window ID>`, repeated shuffling of the current token list only if identical, maximum100 attempts. Control IDs are C001–C144 in protocol category order. Null RNG labels are `<C###>|calibration` and `<C###>|validation`; target label is `K4|conditional-null`.

Each null starts with a fresh copy of the original73 non-crib ciphertext letters, shuffled by its stream RNG; no rolling in-place permutation carries state between nulls. Crib ciphertext letters remain fixed. All null maxima use all1,024×12 hypotheses and exact ties count in the upper tail.

## Model representation and exact ranking

Counts are unsigned64-bit little-endian integers; log tables are IEEE754 binary64 little-endian, flat base26 context-plus-letter indices, orders1,2,3,4 in that order. Counts never cross document boundaries. Training uses1,600,000 letters from the eight fixed capped books. Every smoothed conditional probability row sums to1 within2.23e−16 in the saved model.

Primary summation is a single ordered binary64 accumulation through the three registered blocks, resetting context but not the sum. Then compute `BASELINE + total - (log2(candidate_count)+log2(12))`. The full-key cross-entropy sum is independent. Native/Python synthetic comparisons are bit-exact for all12,288 scores and12,288 full-key cross entropies.

The fixed calibration ceiling is3.6006385531514082 bits/letter, rank337 of340 calibration windows (`ceil(.99*340)`). Every calibration value/window hash is saved; no control-derived adjustment is allowed.

Tableau iteration order is plaintext alphabet AZ/KR, ciphertext alphabet AZ/KR, then Vigenere/Beaufort/variant Beaufort. Ties use ascending candidate alias then lexical tableau ID, regardless of iteration order. Exact equal floating-point scores define ties; a tolerance is not used to create/remove statistical ties. Different-plaintext margin compares the winner with the best score of any other candidate, not the second tableau of the same candidate. Positive recovery requires the selected full key exactly equal the planted key, not merely a correct candidate or apparently English key. Model-label matches are reported separately.

## Retention, limits and audit boundaries

Each actual control/target receipt retains all12,288 candidate/tableau scores, full-key cross entropies, derived keys, bidirectional crypto checks and complete ranking, plus score matrices,1,024 best-per-candidate records with exact prose/provenance and group summaries. Every calibration/validation/target null receipt retains its complete ciphertext/hash, maximum, selected candidate/tableau/key, full-key cross entropy, exact top ties and different-plaintext margin. Full null score matrices are not retained redundantly; deterministic inputs/model/code permit recomputation of the entire searched maximum. No winning alternative is truncated from the defined search.

The synthetic matrix benchmark is approximately0.010seconds per full1,024×12 matrix, excluding Python receipt assembly and independent crypto checks. The registered run is expected to take minutes, comfortably below the60minute/8GB bounds, but actual elapsed time and bytes will be reported. At most8threads share an immutable bank/model. No production scoring before independent implementation/window/model/control audit and a hash-bound freeze.

The accepted speaker/ghostwriter caveat, fixed plaintext-axis key-spelling assumption, conditional-null scope, char-model semantic limitations, and standalone exploratory status remain exactly as in PROTOCOL.md. No ordinary-English claim extends automatically to every English style, other language, key-label convention, or absent plaintext.
