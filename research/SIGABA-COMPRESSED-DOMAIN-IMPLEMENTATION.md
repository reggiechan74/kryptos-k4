# COMPACT-018 phase B — deterministic exact packed cipher sets

Chosen after the retained payload profiles, before implementation/resource outcomes. At the dense guard176 distinct payloads use278,155,004 bytes with534–799 states each, versus482,752 estimated packed bytes. At the separated-window guard192 payloads use291,806,840 bytes with11–51 states each, versus26,852 estimated packed bytes. Estimates concern stored exact sets, not key/solution counts.

Represent a set as either its immutable nonnegative bitmap integer or sorted unique unsigned32 little-endian state IDs. Choose packed storage iff its exact byte-object size4*cardinality+sizeof(empty bytes) is smaller than the bitmap integer's size derived from the highest state and Python digit width. Ties use bitmap. This is deterministic for a set on this runtime; no density threshold is fitted. State IDs must be <2^32. Keep the exact cached hash of the bitmap value: for packed IDs compute the same integer hash via sum(2^id mod P) mod P, where P=sys.hash_info.modulus. Equality never trusts hashes and verifies actual set equality even across representations or deliberately forced test encodings.

Bitmap intersection uses the existing exact predicate then chooses storage anew. Packed intersection independently evaluates every stored cipher start through the five physical rotor tables at its actual offset and keeps exactly the matching IDs; this replaces construction of a whole-torus predicate for an already sparse set. Per-map anchor inverse translates each packed coordinate tuple and re-sorts; bitmap inverse uses the proven torus preimage. No sampling, fitting, probabilistic filtering or discarded branches.

Native output stores exact sets with explicit bitmaphex/u32lehex encoding instead of expanding sparse high state IDs into megabyte hex integers. Raw-key count uses exact cardinality. Tiny verification explicitly decodes to original-start sets and compares independent complete raw-key streams/final offsets. Output and live payload sizes are accounted, with the same256-MiB conservative envelope/output ceiling and1-GiB RSS/headroom. Exhaustive small subsets/intersections, forced-representation equality/hash, per-map inverse, all original tiny fixtures/cache policies and physical traces precede the two unchanged real-sized resource runs. No actual K4 or remote publication.
