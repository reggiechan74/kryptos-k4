# Read-only literal verification utility v1

Purpose: verify one explicitly selected structural literal in pinned Python source without executing any source. This is not a Python interpreter, whole-program proof, cipher/domain validation, or global novelty claim.

Input: source bytes <=262144 bytes (strict UTF-8), exact expected SHA256, nonempty provenance string (pin/URL supplied by operator, not authenticated by this utility), module-top-level plain assignment name, literal dictionary key, and comprehension iterable selector. Expected value is a JSON array of strings. The only supported path is `top-level-name -> dict[key] -> comprehension.generators[0].iter`. Exactly one top-level assignment binding the name is required; single simple Name target only. Exactly one literal-string dictionary key equal to selector is required. Dict unpacking/dynamic keys anywhere in selected dict fail closed. Selected value must be a ListComp, or the exact AST shape `tuple(GeneratorExp)` with one positional argument and no keywords; either comprehension has exactly one non-async generator and no filters. The tuple name is recognized only as a structural wrapper, never called; whether runtime tuple is shadowed is outside semantic scope. Comprehension body is NOT evaluated or interpreted. Iterable must be literal Tuple or List of literal string Constants, <=256 items, each <=256 Unicode codepoints; no calls, names, arithmetic, joined strings, starred expansion or nested values. The expected sequence must match exactly in order and spelling.

This deliberately narrow selector verifies the tuple feeding the motivating `ERRnums['shifts_ST']` or `['shifts_KA']` comprehension. It does not verify the comprehension body, the alphabet definition, later mutations, imported data or runtime reachability. All such claims remain outside scope. Selection is from parsed module structure only; conditional/nested assignments are not selected. Any additional lexical binding of selected name anywhere in the module, including nested scopes, is conservatively rejected to prevent misleading ambiguity. Direct syntactic attribute/subscript writes to the selected name are rejected. Reflective mutations such as globals(), alias mutation and calls like update() are runtime semantics outside this literal-only check, not a guarantee of immutable source meaning. Imports, function arguments, exception names, pattern bindings, deletion, named expressions and augmented assignment that bind the selected name are rejected rather than silently ignored.

Resource guards: source262144 bytes; parse in a separate bounded CLI process when handling untrusted content; AST <=20000 nodes, nesting depth<=80 after parse; Python parser SyntaxError/MemoryError/RecursionError returns failure. JSON request <=65536 bytes, duplicate JSON keys rejected. No eval, exec, imports from source, subprocess spawned from source, network, filesystem writes, or external code execution. CLI reads only explicit request/source files and emits JSON to stdout. CLI POSIX resource limits:2CPU seconds,256MiB address space. In-process library does not establish OS limits; call only with trusted bounded memory or through CLI.

Output: `PASS` only on exact hash, unique supported selector and exact value equality. Otherwise `FAIL` with stable reason. PASS includes sourceSHA256, provenance as supplied, assignment/key/iterable start+end locations, supported selector version, extracted sequence and explicit non-semantic limitation. Never echo whole source or comprehension body.

Validation: development fixtures validate intended narrow path, actual motivating tuple and deliberate wrongpair. Freeze code/spec/development fixture hash manifest BEFORE an independently authored adversarial fixture suite is revealed/run. Reviewer must test unsupported/dynamic/missing/duplicate/binding ambiguity cases, malformed and bounded oversized/deep input, exact locations, Unicode/order/type traps, and no side effects. Actual pinned-source match supplements but cannot replace fresh adversarial validation.
