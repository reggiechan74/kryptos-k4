# Compression source and prior coverage

24 October 2026 UTC. The [contemporary May1989 source-archive index](https://www.tuhs.org/Usenet/comp.sources.unix/1989-May/006017.html) lists compress4.0 in Volume2, ending roughly August1985, and1986Xenix patches. This is primary evidence of pre-1990 availability, not creator use. The attempted TUHS4.3BSD source-tree URL was unavailable through the web tool; no alternate restricted route was used.

[Current ncompress source](https://github.com/vapier/ncompress/blob/main/compress.c) cites Welch's June1984 algorithm and defines legacy magic bytes037/235 octal, code-width bits and block-mode flag. It was read statically, not downloaded/built/executed. Its current source includes later development and is not claimed to be the exact1985 binary. [Maintainer history/rights](https://vapier.github.io/ncompress/) describes the public-domain project. No third-party program source is rehosted here.

The installed macOS `compress(1)` manual identifies adaptive Lempel–Ziv coding and default16/max9..16bits, with code sizes beginning at9bits. Its modern2021manual revision is distinct from its older author/copyright references. Native compressor/uncompressor are the same binary, so their agreement is not independent; the separate arithmetic and shortLZW decoder provide independent controls on the actual short-message domain. Binary hashes are in the run receipt. No code-width transition/CLEAR handling is claimed independently validated by that short decoder.

Prior LANG001/IPA tests cover different representation/transport rules;025lamp/Greek and026tree/geometry/phonetic variants likewise do not test a header-bearing.Zwhole-integer transport. Archive/results gzip files are storage formats, not earlier actual K4 compression tests. The declared8custom radix conventions are exploratory choices, not a historically selected alphabet bridge. Additional encryption, other compressors, header stripping, other alphabets or framing would need a separately justified full specification.
